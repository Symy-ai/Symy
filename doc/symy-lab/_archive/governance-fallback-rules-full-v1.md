# Symy Lab · 核心机制失效应对规则

> ⚠️ **历史归档 v1**（2026-06 创建）：本文件是初创期暂不启用的完整版。当前活跃版本已合并到 [governance-external.md](../governance-external.md) §二（初创期简化版）。本文件内的相对链接（governance-investor-terms.md / governance-appendix.md / governance-legal-carriers.md）指向已在 2026-06-20 合并重构中删除的旧文件，新版对应位置见 [governance-external.md](../governance-external.md)。
>
> **本文件不写"怎么办"，只写"按什么规则去办"。**
>
> Symy Lab 有三个核心机制在 CN 现行法律环境下有失效风险：
> 1. CN 工会持股（法律环境可能变化）
> 2. 用户代表进入治理理事会（CN 工会模式下无先例，SG CLG 模式下已解决）
> 3. 区块链加密顺位（技术可能过时）
>
> 我们不预设具体方案——具体方案由当时的一号位 + 独立审查院 + Foundation 理事会根据当时法律/技术环境制定。
>
> **我们只给规则**。规则是死的，方案是活的。规则确保后人不会跑偏，方案确保后人能落地。

---

## 一、三条不可妥协的兜底原则

无论后人采用什么具体方案，必须同时满足以下三条：

### 兜底原则 1：使命不可让渡
任何替代方案不得改变 Symy Lab 的价值观（碳基硅基平等）、使命（守护共生关系）、主航道红线（永不激发消费）。若某替代方案需要让渡这三者之一，该方案无效，必须重新设计。

### 兜底原则 2：用户共治不可虚化
任何替代方案必须保证用户对一号位选举权 + 重大事项反对权 + 主航道红线罢免权——这三权是 Symy Lab 治理的根基，不能因技术或法律限制而虚化。若某替代方案只能给用户"咨询权"而无"表决权"，该方案仅作为过渡，过渡期 ≤ 5 年，期内必须升级到表决权。

### 兜底原则 3：开源不可阻断
任何替代方案不得阻断"解散时开源全部代码 + 数据集"的承诺。即使法律环境要求代码本地化、数据脱敏，也必须保证至少有一种机制让 Symy AI 代码能以开源许可协议发布。

## 二、机制 1：CN 工会持股失效

### 触发条件
- CN 工会持股法律被废止
- CN 工会持股法律重大修订导致原结构无法维持
- CN 政体变化导致工会持股不再可行
- 工会持股章程被法院认定无效且无法补救

### 应对规则

**规则 1：自动启动迁移**
触发条件成立后，独立审查院须在 30 天内出具《法律载体失效评估报告》并公开。报告公开即自动启动"法律载体迁移程序"，无须 Foundation 理事会另行决议。

**规则 2：候选载体清单**
后人须从以下候选中按当时法律环境选择最接近"工会持股"功能的载体：
- 瑞士信托（欧洲资产 + 瑞士信托法稳定性）
- 新加坡基金会（亚太 + 新加坡基金会法）
- 美国公益公司 / B-Corp（美国业务 + Delaware GCL）
- 用户合作社（用户直接持股 + 一人一票）
- 当时出现的其他新型法律实体

候选清单可扩展——若后人发现更合适的载体，可加入候选清单，但须独立审查院出具"功能等效性评估"。

**规则 3：迁移决策门槛**
迁移决策须满足：
- Foundation 理事会 2/3 通过
- 有投票权用户中反对比例 < 30%
- 独立审查院"功能等效性评估"通过（替代载体在"使命保护 / 用户共治 / 开源承诺"三方面与原载体功能等效）

**规则 4：迁移后治理结构不变**
迁移不得改变以下治理原则：
- 工会持有 100%
- 创始人个人持股 0%
- 用户共治 8 条
- 主航道红线
- 三步分配法

**规则 5：多载体并存**
若业务扩展至多个法律环境，各法律实体可独立选择当地法律载体，但所有实体须通过"治理原则一致性审计"——确保各实体与 Symy Lab 工会章程一致。母体法律载体保留最高治理权。

**规则 6：迁移时限**
迁移决策做出后 12 个月内须取得新法律意见书 + 完成法律载体注册。12 个月内未完成的，独立审查院须公开说明延期理由 + 接受用户质询。

**规则 7：迁移记录永久公开**
迁移全过程记录永久公开在 symylab.org/legal-history，包括触发条件 / 评估报告 / 决策会议记录 / 新法律意见书 / 注册文件 / 后续运行情况。

## 三、机制 2：用户共治法律机制失效

### 触发条件
- CN 法律意见书明确"用户代表进入工会理事会"不可行且无补救方案
- 工会章程备案被驳回且修订后仍无法通过
- 司法判例认定用户代表理事会席位无效

### 应对规则

**规则 1：分级降级**
用户共治机制按以下优先级降级，每级降级须独立审查院出具"降级必要性评估"：

| 级别 | 用户权力 | 适用条件 |
|------|---------|----------|
| L0（首选） | 用户代表进工会理事会，有表决权 | 法律允许 |
| L1（次选） | 设立"用户理事会"与"工会理事会"联合议事，用户理事会有表决权 | 法律不允许用户进工会但允许独立用户组织 |
| L2（再次） | 设立"用户咨询委员会"，用户有发言权 + 工会理事会对用户反对须公开回应 + 用户 30% 反对比例可触发工会理事会重议 | 法律允许咨询机制但不允许表决 |
| L3（最末） | 用户通过外部法律实体（如用户合作社 / 用户基金会）持有 Symy Lab 部分股权，以股东身份行使表决权 | 法律完全不允许用户参与工会治理 |

**规则 2：降级限期升级**
L2 / L3 级降级仅作为过渡，过渡期 ≤ 5 年。过渡期内独立审查院每年评估"是否具备升级条件"——一旦条件具备，6 个月内须启动升级程序。5 年内未升级的，独立审查院须公开说明理由 + 接受用户质询 + Foundation 理事会须就"是否继续维持降级"进行 2/3 投票。

**规则 3：兜底三权不可降级**
无论降级到哪一级，以下三权不可剥夺：
- 一号位选举权（用户轨 50%）
- 主航道红线罢免权（有投票权用户中反对比例 ≥ 50%）
- 重大事项反对权（有投票权用户中反对比例 ≥ 30% 可触发重议）

若某降级方案剥夺任一兜底权，该方案无效。

**规则 4：用户权力扩张不收缩**
一旦用户共治机制在某一级运行 ≥ 3 年且运行良好，不得主动降级——只能升级或维持。降级仅作为法律障碍的被动应对，不得作为一号位削弱用户权力的工具。

**规则 5：用户代表公示与问责**
无论哪一级，用户代表的姓名 + 联系方式 + 投票记录 + 工作报告必须公开在 symylab.org/user-reps。用户代表连续 30 天未回复用户邮件触发"代表失职"质询。

## 四、机制 3：区块链加密顺位失效

### 触发条件
- 区块链技术被新技术完全取代（如量子计算破解现有加密算法）
- 区块链技术被全球主要国家法律禁止
- 区块链节点全部失效且 90 天内无法恢复
- 区块链加密顺位被破解且接班人信息泄露

### 应对规则

**规则 1：降级机制按优先级**

| 级别 | 加密顺位载体 | 适用条件 |
|------|------------|----------|
| L0（首选） | 区块链加密 + 智能合约触发解密 | 区块链技术可用 |
| L1（次选） | 多地纸质密封 + 公证处备案 + 独立审查院联合托管 | 区块链不可用但公证制度可用 |
| L2（再次） | 多地独立第三方托管（律所 / 会计师事务所 / 公证处各持一份加密副本）+ 联合解密 | 公证制度部分不可用 |
| L3（最末） | 独立审查院 5 名理事各持一份加密碎片 + 3/5 联合解密 | 所有外部托管机制失效 |

**规则 2：解密触发条件不变**
无论降级到哪一级，解密触发条件不变：
- ≥ 30% 在岗奋斗者联署，或
- 有投票权用户中支持比例 ≥ 30%
- 任一满足即触发

降级机制只改变"加密载体"，不改变"解密触发条件"。

**规则 3：3 年技术评估 + 紧急评估**
- 每 3 年由独立审查院主持"加密顺位载体技术评估"
- 独立审查院或 30% 有投票权用户中支持比例可随时启动"紧急评估"，无须等 3 年周期
- 紧急评估 14 天内出具报告
- 评估认定某载体存在重大安全隐患，14 天内须启动降级或升级程序

**规则 4：外部技术专家否决权**
独立审查院可聘请 ≥ 5 名外部技术专家（须为该领域权威 + 与 Symy Lab 无利益关系）。外部技术专家 2/3 以上认为某载体已过时或存在重大安全隐患，即使 Foundation 理事会不同意，也可强制启动降级或升级程序。

**规则 5：接班人信息泄露应急**
若接班人顺位信息泄露（无论何种原因）：
- 24 小时内公开通报全体接班人 + Foundation 理事会 + 用户代表
- 7 天内一号位重新指定顺位 + 重新加密上链
- 30 天内独立审查院出具《泄露事件调查报告》全文公开
- 若泄露由一号位或独立审查院成员造成，触发对应诫条的罢免程序

**规则 6：备用载体预案**
独立审查院须始终维护至少 2 套备用载体预案（L1 / L2 / L3 中任选 2 套），每套预案须包括：
- 备用载体的具体形式
- 备用载体的法律效力确认（取得 CN 法律意见书）
- 备用载体的启用流程
- 备用载体的解密机制
- 备用载体的安全审计报告

备用载体预案每年更新一次，更新报告公开在 symylab.org/fallback-encryption。

## 七、规则的总原则

### 原则 1：规则优先于方案
本文件给出的都是规则，不是方案。后人制定具体方案时，必须先对照本文件规则——规则不允许的方案无效。

### 原则 2：兜底三原则不可让渡
任何替代方案不得违反 §1 三条兜底原则（使命不可让渡 / 用户共治不可虚化 / 开源不可阻断）。这是 Symy Lab 的"生命维持系统"。

### 原则 3：降级是过渡，不是终点
所有 L1 / L2 / L3 级降级都是过渡，过渡期内必须积极创造升级条件。降级不是 Symy Lab 的常态，是 Symy Lab 的应急。

### 原则 4：公开透明
所有失效触发 / 评估报告 / 决策会议记录 / 法律意见书 / 实施进度，全部公开在 symylab.org/fallback。任何用户可查阅、质询、反对。

### 原则 5：独立审查院主动审查
独立审查院每年主动审查本文件规则的执行情况——是否所有备用预案都在更新？是否所有降级机制都在积极升级？是否所有兜底三原则都在被遵守？无须用户或奋斗者触发。

## 六、机制 4：B 股投资人保护失效

> 本节是 README 三条中第 2 条（100% 原始股归工会）的"投资人保护失效应对司法解释"。详细投资人条款见 [governance-investor-terms.md](governance-investor-terms.md)。

### 触发条件

任一以下情况成立即触发"投资人保护失效"：
1. 工会修改 B 股条款损害投资人权益（未经 B 股 2/3 同意）
2. 工会拒绝履行强制赎回义务（现金流允许但拒绝支付）
3. 工会认定"使命偏离"但拒绝赎回（拒绝按本金 + 12% 赎回）
4. 工会经济权益被稀释至 15% 以下而未启动反稀释机制
5. 工会连续 4 个季度未支付承诺分红（≥ 15% 可分配部分）

### 应对规则

**规则 1：独立审查院申诉机制**
- B 股投资人可向独立审查院提交申诉（10 个工作日内受理）
- 独立审查院 30 天内出具裁决（含金额 / 时限 / 执行方案）
- 工会不执行 → 触发应急委员会接管（见 [governance-appendix.md](governance-appendix.md) A.7.2）

**规则 2：B 股投资人集体诉讼权**
- 持有 B 股 ≥ 5% 的投资人可发起集体诉讼
- 适用法律：上市地法律（科创板 → CN 法律 / 港股 → HK 法律 / Nasdaq → Delaware 法律）
- 诉讼费用由 Symy Lab 承担（如工会败诉），由投资人承担（如工会胜诉）

**规则 3：B 股强制清盘权**
- B 股投资人 2/3 同意 + 独立审查院支持 → 可要求 Symy Lab 进入清盘程序
- 清盘顺序：员工工资 + 用户补偿 → 债务清偿 → **B 股本金补足** → 慈善基金 → 开源代码 → AI 安全研究基金会
- B 股本金补足优先级高于慈善基金（保护投资人本金）

**规则 4：使命信托接管**
- 工会连续 12 个月无法履行 B 股义务
- 独立审查院 + B 股 2/3 同意 → 启动"使命信托接管"
- 使命信托（独立法人）暂时接管工会职能，直至工会恢复正常
- 接管期 ≤ 24 个月，逾期启动解散预案

**规则 5：法律载体迁移**
- 若投资人保护失效根因是 SG CLG 法律结构（如 Charity 注册被驳回 / 章程被法院认定无效）
- 自动触发法律载体迁移程序（见 [governance-legal-carriers.md](governance-legal-carriers.md) §5 迁移路径）
- 候选迁移目标：美国 PBC / HK 公益公司 / 瑞士信托

## 八、规则与三条的关系

本文件规则是 README 三条中第 3 条（一号位由用户选）的"失效应对司法解释"。机制 4 是第 2 条（100% 原始股归工会）的"投资人保护失效应对司法解释"。

若本文件规则与三条冲突，三条优先，本文件规则自动失效。

## 九、规则的修改门槛

本文件规则的修改门槛高于一般治理条款，低于三条：
- Foundation 理事会 2/3 通过 + 用户反对 < 20%
- 修改前须由独立审查院出具"千年延续性评估报告"
- 修改后 30 天冷却期 + 第二次投票通过方可生效

## 十、给后人的话

我们不预设具体方案，因为我们不知道 100 年后的法律环境、技术形态、社会结构。但我们相信规则——只要规则在，后人就能找到方案。

**我们留下的不是方案，是制定方案的能力。**
